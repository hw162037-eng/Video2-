# Agnes AI Studio Mobile — прототип

## Назначение

Это мобильный WebDev-прототип приложения для локальной работы с Agnes AI Studio. Он переносит основные режимы из приложенного `agnes-ai-studio.html` в интерфейс Expo/React Native и добавляет локальные профили Agnes AI, общий ImgBB-ключ, единый список задач, очередь по профилям и настройки безопасных таймингов.

## Реализовано

| Область | Реализация прототипа |
|---|---|
| Генерация видео | `agnes-video-2.5-flash` с прямой Base64-отправкой; `agnes-video-v2.0` с публичным ImgBB URL для reference/keyframe |
| Генерация фото | `agnes-image-2.0-flash` и `agnes-image-2.1-flash`; text2img, img2img, multi_ref, face_swap |
| Профили | Именованные локальные Agnes AI профили с включением и выключением |
| ImgBB | Один общий ImgBB API key в настройках |
| Очередь | Один общий список задач; отдельная полоса выполнения для фото и видео каждого профиля |
| Параллельность | Один активный фото-запрос и один активный видео-запрос на один профиль; разные профили могут идти параллельно |
| Polling | Видео проверяется по `video_id`, интервал настраивается в секундах |
| Ограничения Free | Защитные интервалы, exponential backoff, обработка 429 и временных 5xx ошибок |
| Ошибки | HTTP-код, сообщение сервера, понятная расшифровка и ручной повтор неуспешной задачи |
| Хранилище | AsyncStorage для состояния; SecureStore для API-ключей на Android с локальным fallback в Web preview |
| Интерфейс | Экраны «Создать», «Задачи», «Настройки» с мобильной тёмной визуальной системой |

## Подтверждённые лимиты Agnes AI Free/default

В публичном официальном каталоге Agnes AI указаны следующие справочные значения фактически исполняемого RPM: текстовые модели — 20 RPM; изображения 1K — 20 RPM, изображения 2K — 10 RPM, изображения 3K и 4K — 1 RPM; видео — 1 RPM. Эти значения могут изменяться, поэтому в production-версии нужно дополнительно показывать пользователю предупреждение о сверке с кабинетом Agnes AI.

Приложение не считает несколько Free API keys способом увеличения общего лимита: официальные материалы указывают, что ключи одного типа используют общий пул. Профили предназначены для удобного хранения и маршрутизации задач, а не для обхода ограничений.

## Важное ограничение текущего этапа

Это согласовательный прототип, а не готовый APK. В Web preview уже работает UI, локальное состояние, постановка задач, API-слой, payload, polling и расчётный прогресс, но настоящий Android WorkManager foreground Worker, тип foreground service `dataSync`, MediaStore-сохранение в `Movies/Agnes-AI` и `Pictures/Agnes-AI`, а также системные тихие/громкие уведомления требуют native Android/custom Expo development build. Эти возможности должны быть подключены следующим этапом без изменения согласованного интерфейса.

## Проверка качества

Команды `pnpm check`, `pnpm lint` и `pnpm test` проходят успешно. Unit-тесты проверяют payload для `agnes-video-2.5-flash` и `agnes-image-2.1-flash`, классификацию временных ошибок, Free rate-limit policy, exponential backoff и расшифровку ошибки 429.

## Следующий этап native Android

Следующая реализация должна копировать выбранные изображения и аудио во внутреннее файловое хранилище приложения до постановки задачи, чтобы фоновые Worker не зависели от временных URI picker-а. Для каждой генерации следует создавать уникальный WorkRequest, запускать его как foreground worker, сохранять состояние в локальной SQLite/Room-базе и восстанавливать его после перезапуска процесса. После получения результата Worker должен скачать файл, записать его через MediaStore, обновить задачу и отправить уведомление с deep link на локальный файл.
